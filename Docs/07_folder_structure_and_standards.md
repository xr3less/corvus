```
corvus/ (repo root)
├── apps/web/               # Next.js 16: landing + dashboard + panel interview + gallery + demo window
├── apps/gateway/           # Node 24 + discord.js v14: N-token host + spec-pointer store (no runtime interpretation, D-012) + supervisor/self-heal

├── .env.example            # all secrets documented (GLM/OpenRouter, Postgres, Creem, Discord app) — no real values
├── .github/workflows/      # ci.yml (typecheck/lint/format/vitest + build-only Docker guard; no eval job, no GHCR push) + deploy.yml (manual GHCR -> SSH compose pull)
└── README.md
```

## 3. Coding standards (objective rules)

_What every piece of code in this repo must do — these are project-independent good practice._

- **Strict typing on.** No untyped escape hatches without a comment explaining why.
- **No hardcoded secrets.** Everything from environment variables. All vars listed in `.env.example` with a comment.
- **Comments explain "why," not "what."** The code says what; comments justify non-obvious decisions.
- **No premature abstraction.** Write the straightforward version first; extract a utility only at 2+ callers.
- **Respect the server/client boundary** (where the stack has one). Never leak server-only code into the client.
- **No dead code, no commented-out blocks** left behind. Delete it; history is in version control.
- **Errors are handled, not swallowed.** Fail loudly in dev, gracefully for users.

## 5. Testing conventions

_Minimal but not zero during validation._

- Unit tests for pure functions (calculations, helpers, serializers).
- At least happy-path + one failure-path test for each API route/critical flow.
- Co-locate tests with the code they test.

> LOCKED D-018: **Vitest** everywhere (unit + API-route + component tests, co-located `.test.*`). Launch-blocker tests run in CI against a real `postgres:17` service container: (A) kill -9 mid-flush loses zero XP; (B) injected crash recovers silently ≤30s with no false page.
